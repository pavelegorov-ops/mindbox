# mindBox

Локальная база знаний по платформе **MindBox** для работы в
[Claude Code](https://claude.com/claude-code). Превращает официальные
документы и админские справочники в Markdown-корпус, по которому
маркетолог может задавать вопросы прямо в чате.

## Что внутри

- **Зеркало Help** (`docs/`) — `https://help.mindbox.ru/docs/` целиком,
  ~650 страниц. Для маркетинговых вопросов: сегменты, кампании, лояльность,
  программы, шаблоны.
- **Зеркало Developers** (`developers/`) — `https://developers.mindbox.ru/docs/`
  целиком, ~370 страниц. Для интеграционных вопросов: HTTP API, SDK
  (JS/iOS/Android/Flutter/RN), webhooks, импорт данных.
- **Генератор сценариев** (`scripts/render_scenarios.py`) — берёт
  hand-written YAML-описания триггерных сценариев, валидирует их и
  генерирует Markdown-карточки с Mermaid-схемой, обратным индексом
  зависимостей и отчётом о проблемах.
- **Slash-команды для маркетолога** (`.claude/commands/`) — `/bootstrap`,
  `/sync-docs`, `/обнови-данные`, `/отправь-данные`. Закрывают
  повседневный workflow без знания git.
- **Заметки** (`notes/`) — приёмы и грабли, которые невозможно вывести
  из кода: как вытащить граф сценария из админки, известные UI-глюки
  MindBox, история эволюции схемы.

Бизнес-данные конкретного тенанта (сценарии, справочник полей рассылок)
живут в **отдельном приватном репозитории** и подключаются клонированием
в `private/<имя>/`. См. [private/_template/README.md](private/_template/README.md).

## Кому полезно

- **Маркетологам Usmall** (и других тенантов на MindBox), которые ведут
  десятки триггерных сценариев и регулярно ищут «как это правильно
  настроить» в документации.
- **Интеграторам**, которым удобнее искать по локальному корпусу и
  цитировать с canonical-ссылкой, чем гонять live-сайт.
- **Командам, использующим Claude Code**, чтобы не объяснять платформу
  каждому новому участнику с нуля — Claude уже знает её через CLAUDE.md +
  локальные корпуса.

## Как начать

См. [BOOTSTRAP.md](BOOTSTRAP.md) — один экран с командами для запуска
с нуля.

## Лицензия и приватность

Скрейперы тянут публичные документы MindBox. Содержимое корпусов
`docs/` и `developers/` — производное от официальной документации
MindBox.

Бизнес-данные конкретного тенанта (имена сценариев, ID сегментов,
кастомные поля клиентов) **никогда не попадают** в этот публичный
репозиторий — они изолированы под `private/<имя>/` и блокируются
`.gitignore`.
