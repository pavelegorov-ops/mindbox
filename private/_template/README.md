# Шаблон тенанта

Этот каталог — **скелет нового тенанта** для движка mindBox. Сам по себе он
ничего не делает: `scripts/render_scenarios.py` его игнорирует (имя
`_template` зашито как исключение в автодетекте активного тенанта).

## Зачем

Движок mindBox разделён на две части:

- **публичный движок** — этот репозиторий: скрейперы доков, генератор
  сценариев, slash-команды Claude Code;
- **приватные данные тенанта** — отдельный репозиторий, клонируется в
  `private/<имя>/` и не попадает в публичный (см. корневой `.gitignore`).

`_template/` показывает, какую структуру должен иметь приватный репо тенанта,
чтобы движок его подхватил.

## Как добавить новый тенант

1. Создайте на GitHub приватный репозиторий, например `mindbox-<company>`.
2. Скопируйте содержимое `private/_template/` в корень нового репо
   (без папки `_template`). При копировании переименуйте
   `engine.txt.example` → `engine.txt`:

   ```
   mindbox-<company>/
     README.md
     engine.txt              # переименовано из engine.txt.example
     mailing-parameters/
       CLAUDE.md
     scenarios/
       src/
       rendered/
   ```

3. Заполните `engine.txt` — минимальная версия движка, с которой ваши данные
   совместимы (формат: `requires_engine >= YYYY-MM-DD` или `>= <commit-sha>`).
   В `engine.txt.example` уже лежит дефолт; обычно достаточно скопировать.
4. На рабочей машине склонируйте этот репо в подкаталог `private/`
   публичного репо движка:

   ```bash
   git clone git@github.com:<org>/mindbox-<company>.git private/<company>
   ```

5. Перезапустите `/bootstrap` в Claude Code — он должен отчитаться
   «активный тенант: <company>».

## Что куда класть

| Папка / файл | Что внутри |
|---|---|
| `engine.txt` | Одна строка: минимальная совместимая версия движка. |
| `mailing-parameters/` | Справочник параметров шаблонов рассылок, выгруженный из админки `<company>.mindbox.ru`. См. `mailing-parameters/CLAUDE.md`. |
| `scenarios/src/<id>.yaml` | Источник правды для каждого сценария — редактируется руками. Формат: `scenarios/schema.md` в корне движка. |
| `scenarios/rendered/` | Markdown, сгенерированный из YAML. Перезаписывается `scripts/render_scenarios.py`. Коммитится вместе с YAML, чтобы ревьюер видел исходник и результат рядом. |
| `backlog/` *(опционально)* | Любые рабочие записки маркетолога: что нужно описать, что разобрать, идеи сценариев. |

## Когда тенантов несколько

Если в `private/` лежит несколько подкаталогов (кроме `_template`),
`scripts/render_scenarios.py` потребует явного выбора (вызывать из
корня репо):

```bash
python scripts/render_scenarios.py --tenant <company>
```
