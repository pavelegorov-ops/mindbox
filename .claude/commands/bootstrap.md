description: Первичная настройка проекта mindBox — venv, проверки, smoke-test, отчёт по тенанту
allowed-tools: Bash, Read, Glob, Grep
---

Пользователь хочет инициализировать проект mindBox с нуля. Эта команда
должна **один раз** настроить рабочую среду и убедиться, что всё на месте.
Никакой сетевой работы по корпусам — для этого есть отдельный `/sync-docs`.

Все шаги выполняй последовательно (не параллельно — каждый зависит от
предыдущего по статусу). Если шаг падает — остановись, объясни проблему
коротко и попроси пользователя что-то сделать.

## Шаг 1. Проверить Python 3 на PATH

```bash
where py 2>/dev/null || where python 2>/dev/null
```

Если ни `py`, ни `python` не найдены — выведи короткую инструкцию:

> Не нашёл Python 3 на PATH. Установи одним из способов:
> ```
> winget install Python.Python.3.12
> ```
> или скачай инсталлятор: https://www.python.org/downloads/windows/
>
> После установки перезапусти терминал и снова вызови `/bootstrap`.

…и остановись.

## Шаг 2. Создать venv и поставить зависимости

Если `.venv/Scripts/python.exe` уже существует — пропусти создание venv,
сразу проверь зависимости. Иначе вызови:

```bash
./scripts/mindbox.bat --dry-run
```

`scripts/mindbox.bat` сам создаст `.venv/` в корне репо, поставит
`requirements.txt` и проведёт тестовый dry-run обоих скрейперов.
**Не запускай его без `--dry-run`** — полная синхронизация это отдельная
команда `/sync-docs`. Если выходной код ≠ 0 — покажи последние ~20
строк лога и попроси пользователя проверить.

## Шаг 3. Проверить корпуса документации

```bash
ls -1 docs/manifest.json developers/manifest.json 2>&1
```

Если оба файла на месте — извлеки `generated_at` из верхушки каждого
(первые ~5 строк) и отчитайся:

> ✅ Корпуса доков на месте.
> docs/ обновлён: <generated_at>
> developers/ обновлён: <generated_at>

Если хоть одного manifest.json нет — мягко скажи:

> ⚠️ Корпуса доков пока не выгружены. Чтобы скачать их (~1000 страниц,
> ~1–2 минуты), вызови `/sync-docs`. Без этого Claude не сможет отвечать
> на вопросы по документации MindBox.

**Не вызывай `/sync-docs` сам** — пусть пользователь решит.

## Шаг 4. Проверить активного тенанта

```bash
ls -1 private/ 2>/dev/null | grep -v '^_template$' | grep -v '^\.' || echo "пусто"
```

Возможные исходы:

- **Пусто** или `private/` нет → отчитайся:

  > ℹ️ Активного тенанта нет. Движок будет работать без бизнес-данных.
  > Чтобы добавить данные тенанта (сценарии, mailing-parameters), склонируй
  > соответствующий приватный репозиторий в `private/<имя>/`. См.
  > `private/_template/README.md`.

- **Один тенант** (например, `usmall`) → читай `private/<имя>/engine.txt`
  и сравни с текущей версией движка. Текущая версия движка — сегодняшняя
  дата (или последний git tag, если в репо уже есть теги). Получить:

  ```bash
  git -C . describe --tags --abbrev=0 2>/dev/null || date -u +%Y-%m-%d
  ```

  Распарси из `engine.txt` строку `requires_engine >= <значение>`. Если
  `<значение>` лексически больше текущей версии движка — выдай
  предупреждение:

  > ⚠️ Тенант `<имя>` требует движок не старше `<значение>`, а текущий —
  > `<текущий>`. Обнови движок (`git pull` в корне репо), иначе валидация
  > сценариев может падать.

  В нормальном случае — отчитайся:

  > ✅ Активный тенант: `<имя>`. engine.txt: `requires_engine >= <значение>` —
  > совместимо с текущей версией движка.

- **Несколько тенантов** → перечисли их и предупреди, что
  `scripts/render_scenarios.py` потребует флаг `--tenant <имя>`.

## Шаг 5. Smoke-test чтения корпуса

Если `docs/summaries.json` на месте — выполни один безобидный grep, чтобы
убедиться, что чтение корпуса работает:

```
Grep "сегмент" docs/summaries.json -B 1 -A 1 | head -10
```

(Используй tool **Grep**, не Bash.) Если получил хотя бы одно совпадение —
отчитайся `✅ smoke-test пройден`.

## Шаг 6. Напомнить про Claude_in_Chrome

Для извлечения сценариев и обновления `mailing-parameters/` прямо из
админки `<тенант>.mindbox.ru` нужно расширение **Claude_in_Chrome**
(устанавливается отдельно в Chrome, не через MCP-конфиг). Просто
напиши пользователю:

> ℹ️ Если планируешь обновлять `private/<тенант>/mailing-parameters/` или
> вытаскивать новые сценарии напрямую из админки — установи расширение
> Claude in Chrome и подключи его к этому Claude Code. Без него работа
> с локальными корпусами и YAML по-прежнему доступна.

## Финальный отчёт

В конце выведи короткую сводку (4-5 строк): что сделано, что в норме,
что требует действия пользователя. Без markdown-заголовков, плоский
список с галочками / предупреждениями. Не повторяй то, что уже
выводилось по ходу шагов — только итог.
