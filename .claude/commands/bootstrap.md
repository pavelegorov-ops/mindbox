Пользователь хочет инициализировать проект mindBox с нуля. Эта команда
**ведёт пользователя за руку**: где можешь — действуешь сам, где нужны
его руки — останавливаешься, чётко говоришь что сделать, и **ждёшь
подтверждения в чате** перед продолжением.

Особенности:

- Пользователь может быть нетехническим (маркетолог). Не сыпь жаргоном:
  не «venv», а «виртуальное окружение Python»; не «PATH», а «системный
  поиск программ».
- Все паузы — явные. После «жди подтверждения» — действительно жди ответ
  в чате, не угадывай.
- Команда триггерится не только по `/bootstrap`, но и по фразам типа
  «настрой всё», «установи всё», «начни настройку».

## Шаг 0. Определить ОС

```bash
uname -s 2>/dev/null || echo Windows
```

| Вывод | Считать как |
| --- | --- |
| `Darwin` | **macOS** |
| `Linux` | **Linux** (ведёт себя как macOS) |
| `MINGW*`/`MSYS*`/`CYGWIN*`/нет команды | **Windows** |

Запомни как `<os>`. Соответствия путей:

| Что нужно | Windows | macOS / Linux |
| --- | --- | --- |
| venv-Python | `.venv/Scripts/python.exe` | `.venv/bin/python` |
| Лаунчер | `scripts/mindbox.bat` | `scripts/sync.sh` |
| Системный Python | `py -3` или `python` | `python3` |

## Шаг 1. Проверить Python

- Windows: `where py 2>/dev/null || where python 2>/dev/null`
- macOS / Linux: `command -v python3 || command -v python`

**Если найден** — отчитайся «✅ Python на месте» (можно с версией) и
иди дальше.

**Если нет — остановись и попроси установить:**

- **Windows** →
  > 🔧 Нужно поставить Python 3.12. Самый простой способ:
  > 1. Открой **PowerShell от имени администратора** (Win → найди
  >    «PowerShell» → правый клик → «Запустить от имени администратора»).
  > 2. Введи команду:
  >    ```
  >    winget install Python.Python.3.12
  >    ```
  > 3. Дождись окончания установки.
  > 4. **Закрой и снова открой Claude Code** (это важно — иначе он
  >    не увидит новый Python).
  > 5. Снова напиши `/bootstrap` или «настрой всё».
  >
  > Если `winget` нет — скачай инсталлятор:
  > <https://www.python.org/downloads/windows/>. **Обязательно отметь
  > галочку «Add Python to PATH»** на первом экране.

- **macOS** →
  > 🔧 Нужно поставить Python 3. Команда:
  > ```bash
  > brew install python3
  > ```
  > Если Homebrew не установлен — поставь его сначала по инструкции
  > на <https://brew.sh> (это одна команда, копируй и вставляй
  > в Терминал).
  >
  > Когда установка закончится — напиши «готов», и я продолжу.

- **Linux** →
  > 🔧 Установи Python:
  > - Debian/Ubuntu: `sudo apt install python3 python3-venv`
  > - Fedora: `sudo dnf install python3`
  > - Arch: `sudo pacman -S python`
  >
  > Когда готово — скажи «готов».

После ответа пользователя повтори проверку. Если Python всё ещё не виден
— скорее всего, не перезапущен терминал. Объясни это и попроси
перезапустить.

## Шаг 2. Проверить Git

```bash
git --version
```

Если есть — отчитайся «✅ Git на месте» и иди дальше.

Если нет — попроси установить:

- **Windows**: <https://git-scm.com/download/win> — стандартный
  установщик, везде «Next».
- **macOS**: `xcode-select --install` (поставит Git вместе
  с инструментами разработчика).
- **Linux**: `sudo apt install git` / `sudo dnf install git` /
  `sudo pacman -S git`.

Жди подтверждения и повтори проверку.

## Шаг 3. Создать виртуальное окружение и поставить зависимости

Если venv-Python (путь из таблицы шага 0) уже существует — отчитайся
«✅ Виртуальное окружение Python уже на месте» и пропусти.

Иначе запусти лаунчер с `--dry-run` — он сам создаст `.venv/` и поставит
зависимости из `requirements.txt`:

- **Windows**:
  ```bash
  ./scripts/mindbox.bat --dry-run
  ```
- **macOS / Linux**:
  ```bash
  ./scripts/sync.sh --dry-run
  ```

  Если `Permission denied` — выполни `chmod +x scripts/sync.sh` и повтори.

**Не убирай `--dry-run`** — полная синхронизация это отдельный шаг.

При успехе: «✅ `.venv/` создан, зависимости поставлены». Если выходной
код ≠ 0 — покажи последние ~20 строк лога, объясни на человеческом
языке, что пошло не так, и попроси пользователя помочь.

## Шаг 4. Запросить приватный репозиторий и склонировать

Проверь, что уже есть:

```bash
ls -1 private/ 2>/dev/null | grep -v '^_template$' | grep -v '^\.' || echo "пусто"
```

### Если пусто — обязательно спроси

Не пропускай этот шаг молча. Дословно:

> 📦 У тебя есть приватный репозиторий с данными твоего проекта в MindBox?
> Это отдельный репо, который должен был дать коллега — там лежат
> YAML-описания триггерных сценариев, справочник полей шаблонов рассылок
> и другие материалы конкретно твоего проекта.
>
> - Если **да** — пришли ссылку (`https://github.com/...`,
>   `git@github.com:...` или ссылка GitLab/Bitbucket). Я сам склонирую.
> - Если **нет** или **«потом»** — скажи «нет» / «пропустить»,
>   и продолжим без него. Движок будет работать с публичной
>   документацией; приватный репо можно подключить позже, повторно
>   вызвав `/bootstrap`.

**Жди ответ.** Возможные ветки:

- **URL получен** — извлеки имя репо (последний сегмент пути,
  без `.git`) и используй как `<имя>`. Подтверди:

  > Склонирую `<URL>` в `private/<имя>/`. Всё верно?

  При «да» / «давай» — выполни:
  ```bash
  git clone <URL> private/<имя>
  ```

  Если упало с ошибкой авторизации (`Authentication failed`, `403`,
  `Permission denied`):

  > 🔐 Не получилось склонировать — нужны права на репо. Проверь:
  > - что коллега действительно дал тебе доступ к этому репо;
  > - что ты залогинен в git-провайдере. Для GitHub самое простое —
  >   поставить GitHub CLI и выполнить `gh auth login`. Альтернатива
  >   — настроить SSH-ключ.
  >
  > Когда разберёшься — напиши «готов», и я повторю клонирование.

- **«Нет» / «пропустить» / «потом»**:

  > ℹ️ Понял. Активного проекта MindBox пока нет. Движок будет работать
  > только с публичной документацией. Когда получишь приватный репо
  > — снова вызови `/bootstrap` и пришли ссылку.

### Если в `private/` уже что-то лежит

Прочитай `private/<имя>/engine.txt`, сравни с текущей версией движка:

```bash
git -C . describe --tags --abbrev=0 2>/dev/null || date -u +%Y-%m-%d
```

Распарси `requires_engine >= <значение>`:

- Если значение лексически больше текущей версии → «⚠️ Проект `<имя>`
  требует движок не старше `<значение>`, а текущий — `<текущий>`.
  Обнови движок (`git pull` в корне репо).»
- Иначе → «✅ Активный проект: `<имя>`. Версия движка совместима».

Если проектов несколько — перечисли и предупреди, что
`scripts/render_scenarios.py` потребует флаг `--tenant <имя>`.

## Шаг 5. Корпуса документации — проверить и предложить скачать

```bash
ls -1 docs/manifest.json developers/manifest.json 2>&1
```

### Оба на месте

Извлеки `generated_at` из шапки каждого:

> ✅ Документация на месте.
> docs/ — обновлено: `<generated_at>`
> developers/ — обновлено: `<generated_at>`

Если `generated_at` старше 30 дней — мягко предложи `/sync-docs`. Не
запускай сам.

### Хоть одного manifest.json нет

**Активно предложи скачать** (это критично для работы):

> 📥 Корпуса документации MindBox ещё не скачаны. Без них я не смогу
> отвечать на вопросы по платформе.
>
> Скачать сейчас? Это ~1000 страниц с help.mindbox.ru
> и developers.mindbox.ru, занимает 1–2 минуты. Скажи «да» — запущу.

При «да» — запусти лаунчер без флагов:

- Windows: `./scripts/mindbox.bat`
- macOS / Linux: `./scripts/sync.sh`

(Используй Bash-таймаут 10 минут на запас.)

После — отчитайся, сколько страниц добавлено / обновлено (см. Summary
в выводе обоих скрейперов).

## Шаг 6. Smoke-test

Если `docs/summaries.json` на месте — выполни безобидный grep, чтобы
убедиться, что чтение корпуса работает:

```
Grep "сегмент" docs/summaries.json -B 1 -A 1 | head -10
```

(Используй tool **Grep**, не Bash.) Если есть совпадение — «✅ smoke-test
пройден».

## Шаг 7. Расширение Claude in Chrome

Напомни (одной фразой, не настаивай):

> ℹ️ Чтобы анализировать сценарии прямо в админке MindBox или
> обновлять `mailing-parameters/`, нужно расширение **Claude in Chrome**
> (ставится в Chrome через Chrome Web Store, не через MCP-конфиг).
> Без него остальная работа с локальными файлами по-прежнему доступна.

## Финальная сводка

Короткая (5-8 строк), без жаргона, дружелюбно. Например:

> 🎉 Готово, можно работать.
>
> ✅ Python и Git на месте
> ✅ Виртуальное окружение `.venv/` поднято
> ✅ Активный проект MindBox: `<имя>` *(или: «без приватного репо —
>    работаем только с публичной документацией»)*
> ✅ Документация выгружена *(или: «документация ещё не скачана —
>    скажи `/sync-docs`, когда захочешь скачать»)*
> ⚠️ Расширение Claude in Chrome не установлено *(опционально)*
>
> Можешь задавать любые вопросы по MindBox — например: «как настроить
> сегмент по дате последнего заказа?» или «какой формат payload у
> webhook integration?».
