Маркетолог хочет синхронизироваться с коллегами — подтянуть всё, что
появилось в обоих репозиториях с момента последней работы.

Не задавай вопросов. Просто выполни шаги, отчитайся коротко в конце.

## Шаг 1. Понять, какой тенант активен

```bash
ls -1 private/ 2>/dev/null | grep -v '^_template$' | grep -v '^\.' | head -1
```

Запомни это имя как `<tenant>`. Если пусто — пропусти шаги, относящиеся
к приватному репо, и работай только с основным.

## Шаг 2. Проверить, нет ли локальных изменений в любом из репо

```bash
git status --porcelain
```

```bash
git -C private/<tenant> status --porcelain 2>/dev/null
```

Если в **любом** из репо есть несохранённые правки — **остановись** и
объясни пользователю по-человечески:

> ⚠️ В <репо> есть несохранённые изменения:
> ```
> M  scenarios/src/Foo.yaml
> ?? scenarios/src/Bar.yaml
> ```
> Прежде чем подтягивать чужие правки, сохрани свои:
>
> - чтобы запушить — вызови `/отправь-данные`
> - чтобы откатить — `git checkout -- <файл>` (внимательно: правки пропадут)
> - чтобы временно отложить — `git stash` (потом `git stash pop`)
>
> Когда разберёшься — снова вызови `/обнови-данные`.

…и не запускай pull. Останавливайся.

## Шаг 3. Подтянуть оба репо параллельно

Если рабочее дерево чистое в обоих:

```bash
git pull --ff-only
```

```bash
git -C private/<tenant> pull --ff-only
```

(Используй `--ff-only`, чтобы не получить случайный merge-commit. Если
fast-forward невозможен — git вернёт ошибку, и ты её покажешь.)

Если один из pull'ов упал из-за несовместимых веток / расхождения —
остановись, покажи последние ~5 строк ошибки и предложи:

> Хочешь, чтобы я выполнил `git pull --rebase` (возможно конфликты)?
> Или сначала проверим, что именно разошлось: `git log HEAD..origin/main`?

## Шаг 4. Сравнить «до» и «после»

Перед каждым `git pull` запомни `HEAD` (через `git rev-parse HEAD`).
После — посчитай разницу:

```bash
git log <pre>..HEAD --oneline
git -C private/<tenant> log <pre>..HEAD --oneline
```

И посмотри, какие файлы изменились в приватном репо:

```bash
git -C private/<tenant> diff --stat <pre>..HEAD
```

## Шаг 5. Отчитайся

Кратко, по-человечески. Пример хорошего отчёта:

> ✅ Готово.
>
> **Движок** (mindBox): подтянул 0 коммитов — был на свежем.
> **Данные тенанта** (usmall): подтянул 3 коммита, изменилось 4 файла:
>
> - 🆕 новый сценарий: `Sc_NewYear_Promo_2026.yaml` (+ его rendered/.md)
> - изменён `Warming-Up-2Order.yaml`
> - обновлён `INDEX.md`
>
> Хочешь, чтобы я перегенерил scenarios/rendered/ через
> `python scripts/render_scenarios.py`, если YAML мог разойтись с
> Markdown? (Обычно коллега уже сам перегенерил и закоммитил, но иногда
> забывают.)

Если ничего не пришло — отчитайся `Уже на свежем — изменений нет`.
