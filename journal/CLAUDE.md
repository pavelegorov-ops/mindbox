# MindBox Journal — локальное зеркало

Эта папка — локальное Markdown-зеркало журнала MindBox
(<https://mindbox.ru/journal/>), поддерживается скриптом
`scripts/scrape_journal.py` в репозитории.

Это **материал для агента, а не для маркетолога**. В отличие от
`docs/` и `developers/` (документация продукта), здесь лежат статьи
журнала — маркетинговые гайды, разборы концепций, кейсы клиентов.
Используй их как источник вдохновения и подтверждение «такое
делали», но **не пересказывай тело статьи целиком** в ответе человеку.

## Подкорпуса

Журнал разделён на секции, каждая лежит в своём подкаталоге со
своими `summaries.json` / `manifest.json` / `pages/` / `index/by-tag/`:

- `journal/education/` — раздел [«Учебные материалы»](https://mindbox.ru/journal/education/).
  Маркетинговые гайды, объяснения концепций, разборы практик
  («что такое CDP», «как настроить ABC-анализ», «как не ошибиться в
  сегментации»). ~380 статей.
- `journal/cases/` — раздел [«Кейсы и экспертиза»](https://mindbox.ru/journal/cases/).
  Истории клиентов: что внедряли, какие механики использовали, какой
  получили результат. ~490 статей.

При поиске темы **проверяй обе секции** через их `summaries.json` —
education и cases часто покрывают одну и ту же тему с разных сторон
(education объясняет «как», cases показывает «как уже сделали»).

## Правила ответа человеку

Общее для обеих секций:

1. **Не вставляй большие фрагменты статьи**. У пользователя есть
   полный текст по ссылке — экономь его время и уважай авторские
   права журнала.
2. **Всегда указывай `source_url`** из frontmatter (он же
   `https://mindbox.ru/journal/<section>/<slug>/`). Это канонический
   адрес статьи.
3. Если на вопрос отвечают несколько статей — перечисли 2–3 ссылки
   списком, по строке на каждую (с заголовком и датой).
4. Если вопрос вообще не покрыт журналом — отвечай по `docs/` или
   `developers/` (см. корневой `CLAUDE.md`). Журнал — дополнительный
   источник, не основной.

### Education — кратко

Сформулируй суть статьи своими словами в **1–3 предложениях**, дай
ссылку. Education — это объяснения и гайды, а не продуктовая истина:
если статья 2017–2020 годов и вопрос про «как сейчас» — добавь
оговорку, что подход мог измениться, и предложи проверить через
`docs/`.

### Cases — чуть подробнее

Кейсы — конкретные истории клиентов, агенту разумнее процитировать
немного больше, чтобы человеку не пришлось обязательно открывать
ссылку для общей картины. В ответе:

1. **Кто и контекст**: 1 строка — название клиента, ниша, исходная
   задача (если очевидна из article).
2. **Какие механики применили**: 2–4 пункта — что именно сделали
   (кампания, сценарий, фича MindBox). Списком, без воды.
3. **Результат**: 1 строка — главные цифры из статьи, если есть
   (выручка, conversion, retention, ROI). Если конкретных цифр в
   статье нет — пропусти, не выдумывай.
4. **Ссылка**: `source_url` обязательно.

**Чего по-прежнему не делать**: дословно переписывать целые
параграфы статьи, перечислять весь процесс детально, дублировать
картинки и таблицы. Кейс — это демонстрация «такое делали», а не
готовое руководство к внедрению; за деталями человек идёт по
ссылке.

Также: **кейс не равен продуктовая истина**. Цифры и подходы могут
относиться к старой версии MindBox, к другому масштабу, к другой
нише. Если человек спрашивает «как мне сделать так же» — отсылай к
`docs/` за каноникой и к `private/<tenant>/scenarios/` за тем, что
уже реализовано в его тенанте.

## Рекомендованный workflow поиска

Для вопросов «что в журнале говорят про X?»:

1. `Grep "X" journal/education/summaries.json journal/cases/summaries.json -B 1 -A 5`
   → ранжированный список карточек с лидами и тегами по обеим
   секциям. Дёшево по токенам.
2. Открыть самую релевантную страницу целиком
   (`journal/<section>/pages/<slug>.md`).
3. Ответить пользователю по правилу секции (см. выше).

Для тематического обзора («дай 3 кейса по retention»):

1. Найти подходящий файл в `journal/cases/index/by-tag/` или
   `journal/education/index/by-tag/` (slug-и транслитерированные:
   `loyalty.md`, `retention.md`, `email.md`).
2. Прочитать его — там уже отобраны статьи с этим тегом и их анонсы.
3. При необходимости открыть полные тексты конкретных статей.

## Структура одной секции (одинакова для education и cases)

- `pages/<slug>.md` — одна статья на файл. Имя файла = последний
  сегмент URL: `https://mindbox.ru/journal/<section>/<slug>/` ↔
  `pages/<slug>.md`.
- `summaries.json` — карточки статей (title, lead, headings, tags,
  published_at). **Сначала grep его** — это в разы дешевле, чем
  читать несколько полных страниц.
- `index/by-tag/<tag-slug>.md` — индекс по тегу. Используй для
  тематических обзоров.
- `INDEX.md` — линейный список всех статей секции по дате
  (свежие сверху).
- `manifest.json` — служебка инкрементальной синхронизации
  (хеш контента и время выгрузки на каждую статью). Руками не править.

## Формат страницы

```yaml
---
title: <человекочитаемый заголовок>
slug: <последний сегмент URL>
source_url: https://mindbox.ru/journal/<section>/<slug>/
published_at: 2023-03-03            # дата публикации (опционально)
modified_at: 2024-10-22             # дата правки (опционально)
description: <короткий анонс из og:description>
tags: [ab-testyi, marketing, ...]   # slug'и тегов
tag_titles: ["AB-тесты", "Маркетинг", ...]   # человеко-читаемые подписи
fetched_at: 2026-05-08T...Z
content_hash: sha256:...
deprecation_hint: ["устарел", ...]   # ОПЦИОНАЛЬНО — см. ниже
---

# <заголовок>

<тело статьи в Markdown>
```

Тело — статья, отрендеренная через markdownify. Внутренние ссылки на
другие статьи **той же секции** переписаны в относительные
`<slug>.md`. Кросс-секционные ссылки (например, education-статья
ссылается на `/journal/cases/foo/`) остаются абсолютными — это
сознательное решение архитектуры. Изображения — абсолютными
CDN-ссылками (`https://image.mindbox.ru/...`), локально не
сохраняются.

### Свежесть статей

У статей есть `published_at`. Журнал не такой динамичный, как
`docs/`, но статьи 2017–2020 годов могут описывать устаревшие
интерфейсы или практики. Это особенно важно для cases: цифры и
подходы кейса 2018 года могут не отражать ни текущие возможности
MindBox, ни актуальные бенчмарки рынка.

### `deprecation_hint`

Появляется, если в теле или заголовке найдены маркеры устарелости:
`устарел`, `устаревш`, `больше не работа`, `больше не поддержив`,
`не используется`, `старый интерфейс`, `старая версия`, `deprecated`,
`прекращ`, `снят с поддержки`, `архивн`. Если поле есть — добавь
оговорку в ответе.

## Обновление

```bash
# обе секции сразу (через оркестратор):
python scripts/sync.py            # инкрементально
python scripts/sync.py --full     # принудительно переписать каждый файл
python scripts/sync.py --dry-run  # показать, что изменится; ничего не пишет

# одна секция:
python scripts/scrape_journal.py --section education
python scripts/scrape_journal.py --section cases
```

Запускать из корня репо. Скрейпер пишет в
`journal/<section>/` относительно текущего каталога.

Скрипт отчитывается: добавлено / обновлено / без изменений / удалено.
Удалённые статьи (slug'и, исчезнувшие из публичного sitemap)
удаляются из `pages/`; восстанавливай из git, если нужно.

Этот `CLAUDE.md` хэнд-мэйнтейнится — скрейпер его не перезаписывает.
