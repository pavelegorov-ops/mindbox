# 👋 Добро пожаловать в mindBox

Этот файл — приветственное сообщение для тех, кто впервые работает
с проектом. Claude использует его, когда пользователь спрашивает
«что это за проект?», «как он работает?», «что внутри?» и т.п.

---

## Что это за проект

**mindBox** — локальная база знаний по платформе **MindBox** для работы
в Claude Code. Вместо того чтобы каждый раз гонять live-сайт с
документацией, всё держится локально как Markdown-корпус. Claude
отвечает на вопросы прямо по нему — со ссылкой на канонический
источник.

Полезен:

- **маркетологам** Usmall и других тенантов — настройка сегментов,
  кампаний, программ лояльности, триггерных сценариев;
- **интеграторам** — HTTP API, SDK (JS/iOS/Android/Flutter/RN),
  вебхуки, схемы импорта;
- **командам на Claude Code** — чтобы не объяснять MindBox каждому
  новому участнику с нуля.

## Как он устроен

Проект состоит из двух частей:

### 1. Универсальный движок (этот публичный репо)

- `docs/` — зеркало <https://help.mindbox.ru/docs/> (~650 страниц,
  для маркетологов).
- `developers/` — зеркало <https://developers.mindbox.ru/docs/>
  (~370 страниц, для интеграторов).
- `scripts/` — скрейперы документации, генератор сценариев из YAML,
  лаунчеры для Windows / macOS / Linux.
- `.claude/commands/` — slash-команды: `/bootstrap`, `/sync-docs`,
  `/обнови-данные`, `/отправь-данные`.
- `notes/` — приёмы и грабли, которые невозможно вывести из кода
  (вытаскивание графов сценариев из админки, UI-глюки MindBox,
  эволюция YAML-схемы).

### 2. Бизнес-данные тенанта (отдельный приватный репо)

Подключаются клонированием в `private/<имя>/`:

- `private/<имя>/scenarios/src/<id>.yaml` — описания триггерных
  сценариев (источник правды).
- `private/<имя>/scenarios/rendered/` — Markdown-карточки,
  сгенерированные из YAML: с Mermaid-схемой, таблицами зависимостей,
  обратным индексом «актив → сценарии», отчётом валидатора.
- `private/<имя>/mailing-parameters/` — справочник полей шаблонов
  рассылок (выгружен с админки).

> Бизнес-данные **никогда не попадают в публичный репо** — изолированы
> под `private/<имя>/` и блокируются `.gitignore`.

## Как это работает на практике

- **Вопрос по документации** → Claude сначала grep'ает
  `docs/summaries.json` или `developers/summaries.json` (лёгкий
  индекс с лидами и заголовками), потом читает релевантную страницу
  из локального корпуса и отвечает с canonical-ссылкой на оригинал.
- **Правка сценария** → меняешь YAML в `private/<тенант>/scenarios/src/`,
  запускаешь `python scripts/render_scenarios.py`, коммитишь и `src/`,
  и `rendered/` в приватный репо. Ревьюер видит исходник и
  сгенерированный Markdown рядом.
- **Документация устарела** → `/sync-docs` подкачает свежие версии
  (~1–2 минуты при первом запуске, дальше инкрементально — только
  изменившиеся страницы).

## Шаг 2 — настрой среду

Чтобы всё это начало работать, нужно **один раз** выполнить:

1. **Поставить Python 3.10+ и Git**, если их нет.
   Подробные команды для Windows и macOS — в [BOOTSTRAP.md](BOOTSTRAP.md).

2. **(Опционально, но рекомендуется)** Склонировать приватный репо
   тенанта в `private/<имя>/`. URL — у того, кто давал тебе доступ
   к проекту. Без этого движок работает, но без бизнес-данных
   (сценариев, mailing-parameters).

3. **Запустить `/bootstrap`** — slash-команда, которая:
   - определит твою ОС;
   - проверит Python;
   - создаст `.venv/` и поставит зависимости из `requirements.txt`;
   - проверит, на месте ли корпуса доков (`docs/`, `developers/`);
   - найдёт активного тенанта в `private/` и сравнит `engine.txt`;
   - прогонит smoke-test чтения корпуса.

4. **Если `/bootstrap` сообщил, что корпуса доков не выгружены** —
   запусти `/sync-docs`. Это потянет ~1000 страниц с
   help.mindbox.ru и developers.mindbox.ru. Без этого Claude не
   сможет отвечать на вопросы по документации.

5. **Дальше повседневно**:
   - `/обнови-данные` — `git pull` сразу в публичном и приватном репо.
   - `/отправь-данные` — закоммитить и запушить правки в приватный
     репо тенанта (с предварительной валидацией YAML и регенерацией
     `rendered/`).

После этого можно просто задавать вопросы: «как настроить сегмент по
оплаченным заказам?», «какой формат payload у webhook integration?»,
«покажи сценарий <id>» — Claude найдёт ответ в локальном корпусе или
в YAML тенанта.
