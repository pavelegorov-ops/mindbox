# Что такое поиск по истории идентификаторов?

Для MindboxID и уникального идентификатора (если не стоит запрет на объединение клиентов с разными ID) доступен поиск по истории.

После объединения клиентов уникальный ID приоритетного клиента станет основным. ID менее приоритетного останется в истории. К клиентам можно по прежнему обращаться по обоим ID. Например, передавать заказы или обновлять информацию. То есть для внешней системы это по прежнему будут два клиента, а в Mindbox один клиент с общим профилем.

С MindboxID все аналогично. Все MindboxID объединенных клиентов хранятся в истории. Особенность в том, что приоритет клиентов не влияет на то какой MindboxID остается у клиента после объединения.

**Пример.**

В базе Клиент1 с CrmID 301 с email1.  
Регистрируется Клиент2 с CrmID 103 и email1.  
Так как email-адреса совпадают принято решение об объединении клиентов. В Mindbox остается клиент с email1 и CrmID 103. CrmID 301 записан **в истории**

Клиенту оформлен заказ. Операция была вызвана для CrmID 103.  
Потом вызвана операция редактирования по CrmID 301 – клиенту добавили номер телефона.

В результате для внешней системы после объединения клиентов ничего не изменилось. Можно делать вызовы используя оба идентификатора (103 и 301). У клиента есть основной ID и еще один записанный в истории. В истории может хранится множество ID.
