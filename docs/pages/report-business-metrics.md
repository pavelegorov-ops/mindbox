# Отчет «Метрики бизнеса»

Отчет формируется за последние два года, даже если на проекте есть данные за более ранние периоды.

Отчет расположен в разделе **Аналитика** → **Метрики бизнеса**.

С помощью отчета можно:

- **Оценить состояние** бизнеса и маркетинга,
- **Отследить причины изменений** в целевых метриках,
- [**Найти точки роста**](how-to-find-growth-points.md.md).

![business-metrics-path.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-path.png)

По умолчанию отчет формируется за последние 12 месяцев с разбивкой по месяцам. Все метрики отображаются по целевому действию «Заказы» и сравниваются год к году.

Данные в отчете за последние 4 месяца (включая неполный текущий) обновляются каждое воскресенье.

При изменении [настроек атрибуции](attribution), при создании нового [целевого действия](goals) и изменении отрасли [бренда](multibrand.md) на проекте данные в отчете пересчитываются за последние 2 года. Обновление происходит в ближайшее воскресенье.

## Настройка отчета

### **1. Выберите период**

Выберите период для отчета. Данные в отчете формируется в разрезе месяца. Правая граница периода включается в отчет.

![business-metrics-date.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-date.png)

### **2. Настройте метрики**

По умолчанию в отчете отображается набор метрик, которые автоматически определяются по наличию данных на проекте. Например, если на проекте нет заказов с выручкой и отправок рассылок, но есть данные по клиентам, подпискам и регистрациям, в отчете будут отображены метрики: «Подписчики», «Получатели», «Регистрации новых клиентов».

Чтобы добавить метрику нажмите «Добавить метрику», выберите нужную из списка и подтвердите выбор. В списке можно выбрать как общие метрики, так и показатели отдельных каналов: рассылок, персонализации сайта, In-App.

![business-metrics-add.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-add.png)

В отчет можно добавить до 4 целевых метрик. Набор метрик бренда сохраняется индивидуально для каждого пользователя.

Чтобы изменить метрику, кликните на значок «Настройки» в правом верхнем углу ее блока.

![business-metrics-edit.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-edit.png)

Для любой метрики в фильтре можно выбрать целевое действие — по каким категориям и статусам заказов посчитать показатель. По умолчанию целевое действие «Заказы» включает статусы: «Оформлен», «Оплачен», «Доставлен».

Для рассылок доступна разбивка по каналам (SMS, email, Webpush, Mobpush) и типам (массовые, автоматические, транзакционные). Для персонализации сайта — по типу формы (попап, встроенный блок, виджет рекомендации).

Также для большинства метрик в фильтре можно выбрать [сегмент жизненного цикла клиента](customer-lifecycle.md) или другой созданный на проекте сегмент.

[Как добавить сегменты для анализа.](report-business-metrics.md#5-dobavte-segmenty-dlya-analiza)

![business-metrics-filter.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-filter.png)

### **3. Настройте график**

График показывает динамику метрик в двух режимах:

- **Сравнение одной метрики год к году**. Чтобы посмотреть данные в этом режиме, достаточно кликнуть на нужную метрику на панели.

![business-metrics-year-to-year.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-year-to-year.png)

- **Сравнение двух метрик друг с другом**. Чтобы добавить или убрать вторую метрику для сравнения, кликните на иконку «Диаграммы» в блоке этой метрики.

![business-metrics-metric-to-metric.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-metric-to-metric.png)

- **Дополнительные настройки отображения**. Под графиком находится кнопка, которая открывает меню настроек отображения. При необходимости добавьте на график отображение точек данных, настройте прирост и др.

![business-metrics-graph.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-graph.png)

### **4. Влияние сегментов на метрики**

Отчет распределяет клиентов в сегменты [по этапам жизненного цикла](customer-lifecycle.md) и рассчитывает их влияние на выбранную метрику. По умолчанию в разделе отображается метрика «Количество клиентов». Чтобы изменить метрику и ее настройки, кликните на поле с метрикой:

![business-metrics-lifecycle-metrics.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-lifecycle-metrics.png)

По кнопке «Отчет по сегментам» можно перейти в **отчет по сегментам**. [Подробнее про отчет](segments-dashboard.md).

![business-metrics-lifecycle-report.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-lifecycle-report.png)

Так как в сегментах «Новички без заказа», «Предотток», «Отток» и «Без заказа» отсутствуют заказы, в метриках, связанных с продажами, для этих сегментов **не будет данных**.

### 5. Добавьте сегменты для анализа

Нажмите кнопку **«Добавить сегмент»** в отчете «Влияние сегментов на метрики» и выберите до 30 сегментов.

Для выбора доступны [статические](https://help.mindbox.ru/docs/segment-client-static), [пересчитываемые](https://help.mindbox.ru/docs/segment-client-filter-recalculate) и [RFM-сегменты](https://help.mindbox.ru/docs/%D0%BA%D0%B0%D0%BA-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0%D0%B5%D1%82-rfm-%D1%81%D0%B5%D0%B3%D0%BC%D0%B5%D0%BD%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5) по клиентам.

![business-metrics-lifecycle-segments.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-lifecycle-segments.png)

После сохранения выбранные сегменты пересчитываются по [метрикам](https://help.mindbox.ru/docs/report-business-metrics#metriki) отчета.

Исключение

Сегменты **не** рассчитываются по метрикам:

- Доля выручки из рассылок
- Конверсия в первый заказ
- Конверсия в повторный заказ
- Конверсия в первый заказ из рассылок
- Конверсия в повторный заказ из рассылок

По метрике «Подписчики» данные доступны только **за последний месяц**.

Данные по сегмента доступны с момента создания сегмента и будут пересчитаны к следующему понедельнику после еженедельного пересчета отчета.

Примечание

Если сегмент существует более двух лет, будут доступны данные только за последние два года.

[**Как считаются метрики по добавленным сегментам**](report-business-metrics.md#segments-recalculation)

- В отчет попадают только те события, которые произошли в период, когда клиент находился в выбранном сегменте.
- Момент попадания в сегмент для расчета метрик сдвигается **на 00:00 предыдущего календарного дня**.

Такой подход позволяет сохранить логику анализа в отчете при учете задержки попадания в сегменты (например, из-за пересчета сегмента по расписанию или ожидания импорта в статический сегмент).

**Пример 1. Первый заказ клиента.**

Клиент сделал первый заказ 03.12 в 16:00, а в сегмент «Клиенты с заказами» попал только во время следующего пересчета 04.12 в 08:00. Отчет учитывает его данные в рамках сегмента «Клиенты с заказами», начиная с 03.12 00:00.

**Пример 2. [Реактивация клиентов по заказам](workflow-reactivate.md).**

На проекте вручную созданы и добавлены в отчет два пересчитываемых сегмента: «Отток» и «Активные клиенты».

**Как происходит реактивация клиента:**

- 09.12 00:00 — клиент находится в пересчитываемом сегменте «Отток».
- 10.12 12:00 — клиенту была отправлена реактивационная рассылка.
- 15.12 10:00 — клиент переходит на сайт через письмо и оформляет заказ.
- 16.12 03:00 — происходит пересчет сегментов: клиент выходит из «Оттока» и переходит в пересчитываемый сегмент «Активные клиенты».

**Как это отобразится в отчетах:**

- **«Влияние сегментов»**: в итоге пересчета метрик попадание клиента в сегмент «Активные клиенты» сдвинется на 15.12 00:00, поэтому выручка от заказа попадет в сегмент «Активные клиенты».
- «[**Эффективные кампании**](report-business-metrics.md#6-effektivnye-kampanii)»: сдвиг при пересчете сегментов также применится. В данном случае метрики рассчитываются **от даты отправки рассылки**. Поэтому выручка от заказа клиента [атрибутируется](attribution.md) к тому сегменту, в котором клиент был на момент 09.12 в 00:00 — к сегменту «Отток».

При оценке эффективности реактивации учитывайте особенности пересчета сегментов в разных отчетах и ориентируйтесь на отчет по рассылкам.

### **6. Эффективные кампании**

Отчет «Эффективные кампании» собирает данные о сценариях и рассылках по трем метрикам: «Выручка из конверсий», «Получатели» и «Выручка на получателя». По этим метрикам можно определить, насколько эффективна кампания в разрезе целевого действия и сегмента жизненного цикла клиента.

- **Выручка из конверсии** — суммарная выручка от заказов, [атрибутированных к кампании](attribution.md) в рамках целевого действия, которые были поставлены на отправку в выбранном периоде. Заказы могут быть совершены не в выбранном периоде.
- **Получатели** — среднемесячное количество клиентов с хотя бы одной доставкой рассылки в рамках кампании за выбранный период. Метрика рассчитывается только за месяцы с отправками кампании. Учитываются отправки на момент нахождения клиента в выбранном сегменте.
- **Выручка на получателя** — отношение выручки от заказов, [атрибутированных к кампании](attribution.md) в рамках целевого действия, к получателям кампании. Метрика рассчитывается только за месяцы с отправками кампании.

Укажите, по какому целевому действию и по какому сегменту клиентов должны отображаться данные. Далее выберите тип кампании через переключение между вкладками: «Сценарии» или «Массовые».

![business-metrics-lifecycle-tabs.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-lifecycle-tabs.png)

Список сценариев можно дополнительно ограничить только по активным кампаниям. Если эта настройка выключена, завершенные сценарии будут отображены серым цветом.

![business-metrics-lifecycle-inactive.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-lifecycle-inactive.png)

Для более подробных данных перейдите в [отчет по рассылкам](mailings-dashboard.md) или [отчет по сценариям](flows-dashboard.md) по клику на любую кампанию.

| Заказы | Количество заказов из *сегмента участников* или *неучастников* программы лояльности |
| Средний чек | Средний чек в *сегменте участников* или *неучастников* программы лояльности |
| Аплифт среднего чека | Разница между средним чеком участников и *неучастников* программы лояльности |
| Начислено баллов | Количество баллов, начисленное *участникам ПЛ* |
| Списано баллы | Количество баллов, списанных *участниками ПЛ* |
| Темп списания баллов | Доля списанных баллов от начисленных. Сгоревшие баллы в списанных **не учитываются**. |
| Общая сумма скидок | Сумма скидок сегмента *участников ПЛ* |
| Доля скидки | Процентное отношение суммы скидок сегмента *участников ПЛ* к общей выручки |

## Цели

**Цель** — это показатель бизнес‑метрики, который планируется достичь за заданный срок в результате маркетинговых кампаний.

Цели позволяют:

- Иметь четкое представление о результатах и путях ее достижения
- Отслеживать текущий прогресс выполнения

В одном бренде доступно для создания 4 цели.

**Как перейти к настройке:**

1. Нажмите «Добавить цель»:

   ![business-metrics-new-goals](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-new-goals.png)
2. Настройте цель:

   - **Метрика** — показатель, в рамках которой будет оцениваться результат;
   - [**Целевое действие**](https://help.mindbox.ru/docs/goals) для ряда метрик;
   - **Сегмент клиентов**;
   - **Период цели** - за какой срок планируется достигнуть поставленный результат;
   - **Целевое значение** — конечный результат цели;
   - **Гипотезы** достижения цели.

   ![business-metrics-new-goals-settings.png](https://storage.yandexcloud.net/assets-help-mindbox-ru/images/business-metrics-new-goals-settings.png)

По одной метрике можно настроить несколько целей для разных задач. Например:

- стратегическая цель по выручке на полгода или год;
- тактическая цель по выручке на ближайший месяц.

Это позволяет одновременно держать в фокусе и долгосрочное направление, и краткосрочные приоритеты.

## Как удаление данных отражается на отчетах

- **Автоматическое удаление клиентов**. Влияет только на число клиентов и подписчиков в отчете. Заказы удаленных покупателей по-прежнему будут учитываться в других метриках. Поэтому данные по заказам и среднему чеку могут отличаться от данных по фильтрам.
- **Автоматическое удаление действий клиентов** не влияет на отчет — данные действий сохраняются и учитываются в метриках.
- **Ручное удаление клиентов или действий** за четыре последних месяца учитывается в метриках отчета — данные в отчете обновятся. Удаление действий старше четырех месяцев на данные отчета не влияет.

При изменении настроек целевого действия или атрибуции отчет автоматически пересчитается за 2 года в ближайшее воскресенье. В рамках этого пересчета будут учтены все удаленные данные по заказам и клиентам, которые произошли в пересчитываемый период.

## Ответы на частые вопросы

1. Почему метрика в отчете «Метрики Бизнеса» расходится с такой же метрикой в другом отчете Mindbox (отчет по рассылкам, сценариям, персонализации)?

   - **Причина 1: Разная группировка данных в отчетах.** В отчете «Метрики Бизнеса» данные группируются помесячно, в других отчетах Mindbox — за конкретные даты. В отчете «Метрики Бизнеса» данные за текущий месяц всегда будут неполными.
   - **Причина 2: Разная частота обновления отчетов**.  
     Отчет «Метрики Бизнеса» обновляется раз в неделю, а отчет по рассылкам, к примеру, обновляется каждый день.
   - **Причина 3: Данные в отчетах обновляются за разный период.** В отчете «Метрики бизнеса» данные пересчитываются каждую неделю за последние 60 дней, в отчете по рассылкам — за последние 90 дней. Из-за этого в отчетах по-разному может учитываться импорт и удаление данных.
2. Как влияет изменение статуса заказа (например, отмена) на его отображение в отчете? В каких случаях заказ исчезнет из отчета, а в каких — останется?

   - Заказы со статусами «Отменен» и «Возвращен» исключаются из отчета и не учитываются при расчете метрик. Кроме того, в отчет попадают заказы только в тех статусах, которые указанны в настройках целевого действия.

Заданы в Настройки → Лояльность → Настройки программы лояльности.

Неучастниками считаются как идентифицированные, так и анонимные клиенты.
