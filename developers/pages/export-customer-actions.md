# Экспорт действий клиентов

## Общий контракт постановки задачи экспорта

Общий контракт постановки задачи экспорта описан [здесь](exports-overview.md)

## Контракт экспорта действий клиентов

**Пример запроса**

```
POST https://api.mindbox.ru/v3/operations/sync?endpointId={endpointId}&operation={operation}
Accept: application/json
Content-Type: application/json
Authorization: SecretKey {Секретный ключ}

{
  "sinceDateTimeUtc": "<Дата и время самого раннего действия (UTC, YYYY-MM-DD hh:mm)>",
  "tillDateTimeUtc": "<Дата и время самого позднего действия невключительно (UTC, YYYY-MM-DD hh:mm)>",
  "segment": {
    "ids": {
      "externalId": "<Внешний идентификатор сегмента по действиям>"
    }
  }
}
```

Во входных параметрах можно указать:

- Дату "от" (sinceDateTimeUtc) в формате UTC. Тогда в выгрузку попадут только действия созданные в системе после этой даты
- Дату "до" (tillDateTimeUtc) в формате UTC. Тогда в выгрузку попадут только действия созданные в системе до этой даты
- externalID сегмента действий, если таковой не был выбран в настройках шага операции.

"Дата создания действия в системе" - это дата, когда Mindbox обработал это действие, фактически, действие могло быть совершено клиентом в другое время. Это важно учитывать, когда оперируете периодом в запросе выгружаемых данных.

Проверка попадания действия в запрошенный период происходит следующим образом:  
Дата "от" <= дата создания действия в системе < даты "до"

Помимо базовых полей, в настройках шага можно выбрать дополнительные сущности, которые могут попасть в выгрузку, если действие имеет связанные данные. Например, действие оформления заказа связано с заказом, а клик по письму из рассылки с сущностью рассылки.

## Рассылка

Для выгрузки взаимодействий с рассылками используйте [экспорт статусов](export-mailing-statuses.md#/).

```
{
  "customerActions": [
    {       
      <Базовые поля>,
      "rootAction": {      
        "ids": {
          "mindboxId": <Идентификатор Mindbox>
        },
        "actionTemplate": {
          "ids": {
            "systemName": "<Системное имя шаблона действия>"
          },
          "name": "<Имя шаблона действия>"
        },
      },        
      "mailing": {
        "name": "<Название рассылки>",
        "ids": {
          "systemName": "<Системное имя рассылки>",
          "id": "<Идентификатор Mindbox>",
          "variantNum": "<Номер варианта рассылки>"
        },
        "action": "<Событие в рассылке>",
        "notSentReason": {
          "ids": {
            "systemName": "<Системное имя статуса, почему рассылка не отправилась>"
          },
          "name": "<Описание статуса, почему рассылка не отправилась>"
        },
        "notDeliveredReason": {
          "ids": {
            "systemName": "<Системное имя статуса, почему рассылка не доставилась>"
          },
          "name": "<Описание статуса, почему рассылка не доставилась>"
        },
        "link": "<Ссылка>",
        "viewEmailMessageUrl": "<Ссылка на просмотр отправленного сообщения>"
      }
    }
  ]
}
```

Действия по рассылке:

- Dispatch - Рассылка
- MailingSend - Рассылка отправлена
- MailingOpen - Рассылка открыта
- MailingNotSent - Рассылка не отправлялась
- MailingNotDelivered - Рассылка не доставлена
- MailingClick - Клик по ссылке в рассылке
- WaitingForDispatch - Участие в рассылке
- MailingUnsubscribe - Запрос отписки от рассылок

Статусы, почему рассылка не отправилась:

- ContactMissing - Отсутствует контакт
- InvalidContact - Невалидный контакт
- WaitingForConfirmationSubscriptionStatusRequried - Статус подписки потребителя должен быть "Требует подтверждения"
- CustomerUnsubscribed - Клиент отписан от рассылок
- CustomerInGlobalControlGroup - Клиент в глобальной контрольной группе
- CustomerInMailingControlGroup - Клиент в контрольной группе рассылки

Статусы, почему рассылка не доставилась:

- EmailBlackList - [Email]: Отклонено, т.к. адрес в "черном" списке
- EmailConnectionFailureOnSending - [Email]: Произошел обрыв соединения при отправке
- EmailInactiveAccount - [Email]: Ящик неактивен или отключен
- EmailIncorrectAddressFormat - [Email]: Неверный формат адреса
- EmailMailboxFull - [Email]: Ящик переполнен
- EmailMxRecordWasntResolved - [Email]: На указанном домене отсутствует почтовый сервер
- EmailNonExistingAddress - [Email]: Несуществующий адрес
- EmailReceiverServerIsUnavailable - [Email]: Сервер получателя недоступен
- EmailRejectedBecauseOfContent - [Email]: Отклонено из-за содержимого
- EmailRejectedWithUnknownReason - [Email]: Отклонено по неизвестной причине
- EmailServerProtocolOrTimeoutError - [Email]: Ошибка протокола или превышение ожидания ответа сервера
- UnknownError - [Email]: Неизвестная ошибка

## Связанное изменение баланса

```
{
  "customerActions": [
    {
      <Базовые поля>,
      "customerBalanceChanges": [
        {
          "balanceType": {
            "ids": {
              "systemName": "<Системное имя балльного счёта>"
            },
            "name": "<Название балльного счёта>"
          },
          "changeAmount": "<Сумма изменения баланса>",
          "availableFromDateTimeUtc": "<Дата доступности баланса>",
          "expirationDateTimeUtc": "<Дата сгорания баллов>",
          "comment": "<Комментарий к изменению баланса>",
          "balanceChangeKind": "<Вид изменения баланса>"
        }
      ]

    }
  ]
}
```

Вид изменения баланса может принимать следующие значения

| Системное имя | Тип изменения | Поле отображения |
| --- | --- | --- |
| Expired | Сгорание баллов | Сгорание баллов |
| Custom | Корректировка баллов триггером или ручная корректировка | "Comment" или "Начисление баллов" |
| RetailOrderBonus | Баллы за заказ, могут быть положительные и отрицательные, в случае возвратов | Бонус за заказ |
| RetailOrderPayment | Баллы, потраченные за заказ. Могут быть отрицательные и положительные в случае возврата | Списание за заказ |
