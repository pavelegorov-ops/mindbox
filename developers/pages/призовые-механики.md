# Призовые механики

Призовые механики позволяют выдавать призы потребителям. Призы выдаются в обмен на бонусные баллы или за выполнение каких-то действий-условий.  
Призовые механики заводятся в кампании, призы добавляются в механику. И призам, и механикам можно задать ограничение доступности по времени или по фильтру доступности.

Фильтр доступности однозначно определяет какой именно потребитель может получить приз. Фильтр доступности индивидуален для каждого приза и проверяется в момент выдачи приза потребителю. У механики тоже есть фильтр доступности.  
При проверки доступности приза потребителя оба фильтра соединяются через “И”.  
Задавать фильтр доступности не обязательно.

Призовая механика может быть связана с балльным счетом — это позволяет снимать баллы с потребителя при выдаче ему приза. У приза при этом указывается стоимость в баллах.

## Типы призов

При создании приза вы указываете его тип:

- Мобильный платеж — при получении такого приза потребителю на его мобильный телефон уходит платеж с фиксированной суммой, сумма задается при создании приза.
- Заявка на получение приза — используется в «одежных» механиках, когда для получения футболки правильного размера нужно сначала получить "заявку на получение футболки", а уже потом по заявке выбрать футболку нужного размера, либо когда есть пул равноценных призов (iPhone 7 разных цветов) и только один из них предлагается выбрать по заявке.
- Основной тип — как правило это материальный приз, либо просто пометка о призе, а само награждение происходит по каким-то вашим внутренним правилам.
- Промокод — наш стандартный промокод, который потребитель может погасить и получить скидку или подарок.

## Призовые механики

При создании призовой механики вы указываете ее тип:

- Магазин — потребитель выбирает приз и получает его в обмен на баллы, участвуют все призы, кроме заявок.
- Выдача заявок — потребитель выбирает приз типа "Заявка на получение приза" и получает ее в обмен на баллы.
- Ручная выдача — по итогам розыгрыша на стороне сайта или творческого конкурса потребителю выдается приз. Заранее неизвестно, какой из потребителей получит приз. Не должна использоваться, когда за какое-то действие все потребители обязательно получают хоть какой-нибудь приз.
- Гарантированный приз — за некоторые действия потребителей им гарантированно выдается приз или заявка. Призы из такой механики можно выдавать в триггере по событию, так получится почти моментальный розыгрыш.

# Выдача через триггер

Для этого заведите механику, добавьте в нее призы. Настройте триггер по событию: потребитель совершил целевое действие, что-то купил и проч. В условиях запуска триггера укажите "Приз доступен". Готово — при появлении событий, подходящих под фильтр, потребители начнут получать призы.

# Выдача через сервисы

Рассмотрим стандартный магазин с широким сценарием - много призов и есть возврат приза.  
По шагам

1. Потребитель получает информацию о призах в магазине (ссылка)
2. Потребитель получает информацию о конкретном призе (ссылка)
3. Потребитель получает приз (если за баллы - они автоматически снимутся) (ссылка)
4. Потребитель находит приз в списке полученных призов в личном кабинете (ссылка)
5. Потребитель возвращает приз обратно (опционально, но возможно) (ссылка)

С точки зрения разработчика  
В шаге 1 вы получаете системные имена всех призов.  
В шаге 2 по конкретному системному имени приза запрашиваете подробную информацию о нем - доступность, дополнительные поля и проч.  
В шаге 3 передаете системное имя выбранного приза в сервис выдачи приза  
В шаге 4 получаете информацию обо всех призах потребителя, включая их ИД  
В шаге 5 передаете ИД приза из шага 4 в сервис возврата приза.

Опция для включения функционала — «Призы, розыгрыши, конкурсы».
