# Предварительный расчет заказа с процессингом

AuthorizedPreorder

---

## Набор шагов

Операция расчёта скидок перед продажей, или пречека, состоит из следующего набора шагов:

| Шаг | Описание |
| --- | --- |
| Клиент - Авторизованный - Получить существующего, ищем по... | Предназначен для поиска клиента в базе данных Mindbox. Поиск может происходить по различным (одному или нескольким) параметрам, которые выбираются из выпадающего списка. |
| Заказ - Процессинг - Расчёт заказа - с режимом арбитража в Mindbox | Предназначен для расчёта итоговой стоимости заказа со всеми применимыми к нему скидочными акциями, помокодами и т.д. [Арбитраж](https://help.mindbox.ru/docs/promotion-rules) между применяемыми акциями будет действовать так, как он задан в Mindbox. |
| Действие - Переопределить точку контакта | Предназначен для записи, в какой именно точке контакта (магазине) происходит расчёт заказа. Это нужно делать, например, для того чтобы применились (или не применились) акции, у которых выставлено ограничение по месту действия. Подробнее о промоакциях и их настройках можно прочитать [тут](https://help.mindbox.ru/docs/how-to-create-a-discount-promo). |
| Клиент - Получить данные по текущему клиенту (Статус обработки, идентификаторы клиента) | Предназначен для того, чтобы в ответ операция вывела статус выполнения (успешно ли она рассчитала заказ), а также различные идентификаторы клиента для дальнейшего взаимодействия с ним. |

## Описание метода

Осуществляется с помощью POST-запроса. Название операции настраивается в системе Mindbox.

Сервис используется в корзине интернет-магазина или на кассе оффлайн-магазина. В сервис передается полный состав заказа со всеми внешними акциями, которые нужно к нему применить.

В ответ возвращается информация о заказе с пересчитанными ценами (с учетом активных в данный момент промоакций, промокодов и других скидок), и детальной информации о всех скидках, запрошенных покупателем.

В процессе расчета скидок Mindbox может разделить одну линию на несколько. Подробнее о распределении скидок можно почитать [тут](https://help.mindbox.ru/docs/split-and-spread). В этом случае в ответе вернется несколько линий с одинаковым lineId, по которому клиент может понять, какая именно позиция была разделена. Клиент должен корректно обработать такую ситуацию и каждой новой линии присвоить свой уникальный идентификатор для последующих запросов.

При этом Mindbox автоматически проставит порядковые номера позиций в узле lineNumber.
Порядковые номера позиций влияют на логику применения скидок. В дальнейших запросах необходимо передавать порядковые номера, полученные от Mindbox.

### Описание узла Order

Узел **Order** передаёт детальную информацию о рассчитываемом заказе.

- Узел **Ids** передаёт информацию об Id уже созданного заказа.
  Id уже существующего заказа указывается для того, чтобы пересчитать его с новыми данными (например, если решили убрать или добавить один из продуктов в состав заказов). Расчёт заказа будет произведён с теми акциями и бонусами, которые были доступны клиенту на момент первого сохранения заказа.
- Узел **area** — это узел, передающий информацию о зоне (например, об области или часовом поясе), в которой оформляется заказ.
- Узел **bonusPoints** — это узел, передающий информацию о баллах к списанию за заказ. В поле **amount** необходимо передать количество баллов, которое хочется списать. Если переданная сумма скидки баллами превысит стоимость заказа, система автоматически спишет число баллов, эквивалентное стоимости линий, не превышая его.
- Узел **coupons** — это узел, передающий информацию о промокодах, которые необходимо применить к заказу. В поле **Code** передаём значение нужного промокода.
- Поле **deliveryCost** передаёт стоимость доставки заказа. Доставка учитывается в общей стоимости при оплате, однако это поле необязательно.
- Массив **lines** передаёт информацию обо всех линиях чека. В одной линии могут содержаться только одинаковые продукты. Для каждой отдельной линии есть свой узел, который передаёт информацию о ней. Узел содержит:

  - Узел **Product**, который передаёт информацию о конкретной позиции в линии. В нём указываются **Ids** продукта — идентификатор продукта во внешней системе.
  - Поле **lineNumber** — это порядковый номер линии, должен по порядку возрастать с каждой новой линией в заказе. Данное поле является необязательным. Если оно не заполнено, Mindbox проставит порядковые номера автоматически.
  - Поле **lineId** — это уникальный идентификатор линии заказа. Это необязательное поле, оно может генериться автоматически.
    Несмотря на первичное сходство, lineNumber и lineId - это разные параметры. Различия проявляются в ситуации, когда при расчёте заказа одна линия поделилась на несколько. Подробно о ситуациях, в которых линия заказа может быть разбита на части, можно почитать [тут](https://help.mindbox.ru/docs/split-and-spread). Если происходит сплит и из одной линии чека мы получаем две, её номер меняется и увеличивается у новой линии, а их идентификатор остаётся прежним. Это сделано для того, чтобы по идентификатору было понятно, откуда взялась новая линия, с чем она была слита, а по её номеру было понятно, к какой именно стоимости (и к каким бонусам) апеллировать при возврате.
  - Поле **quantity** — количество товаров в линии. Может быть как целым, так и дробным числом, в зависимости от специфики товара. Принимает максимум 3 знака после запятой.
  - Поле **quantityType** — тип количества товара (целое или дробное). Его нужно передавать (с типом **double**) только в случае, если количество товара должно быть дробным.
  - Поле **basePricePerItem** — цена за единицу продукции в линии. Обязательное поле, у всех продуктов в одной линии значение должно быть одинаковым. Принимает максимум 2 знака после запятой.
  - Поле **minPricePerItem** — минимальная цена за единицу продукции в линии. Необязательное поле, показывает стоимость товара, ниже которой, даже при действии всех возможных скидок, опускаться нельзя. У всех продуктов в одной линии это значение должно быть одинаковым. Принимает максимум 2 знака после запятой.
  - Поле **customFields** — это узел, передающий дополнительную информацию по продуктам в линии. Необязательный узел.
  - Поле **status** — это системное имя статуса позиций в линии.
  - Узел **requestedPromotions** — узел, для применения внешних промоакций.

    - В поле **externalId** указываем идентификатор внешней промоакции, которую нужно применить.
      - В поле **type** указываем, что это внешняя акция (**discount**).
        - В поле **amount** передаём размер скидки в рублях.

### Создание внешних промоакций

Перед применением внешних промоакций их нужно добавить в систему через API или операцию.
Они появятся в дереве промоакций, и после этого их можно будет применять к заказу.

- Узел **payments** передаёт информацию о способах оплаты, примененных к заказу. В поле **type** передаётся тип оплаты.
- Узел **cashdesk** в поле **Ids** передаёт идентификатор кассы, где производится оплата. Поле необязательное.

### Описание узла Customer

Узел **customer** несёт информацию о клиенте, переданном в запросе операции.

Данные о клиенте, которые операция будет возвращать, можно указать в её настройках.

- Поле **processingStatus** показывает, какой статус процессинга у клиента, по которому производился расчёт заказа. Может принимать одно из значений:

  - **NotChanged** — было редактирование клиента без изменений;
  - **Changed** — было редактирование клиента с изменениями;
  - **Created** — клиент был успешно создан;
  - **NotFound** — клиент не найден в системе;
  - **Found** — клиент успешно найден в системе;
  - **AlreadyExists** — клиент уже существует;
  - **Ambiguous** — по указанным данным поиска найдено несколько клиентов.
- Поля **firstName**, **middleName** и **lastName** передают Имя, Отчество и Фамилию клиента соответственно, если они заполнены.
- Поле **email** передаёт почту клиента, если она заполнена.
- Поле **isEmailInvalid** показывает, валидный или невалидный e-mail у клиента:

  - **False** - если e-mail валидный;
  - **True** - если e-mail невалидный.
- Поле **mobilePhone** передаёт номер мобильного телефона клиента, если он заполнен.
- Поле **isMobilePhoneInvalid** показывает, валидный или невалидный телефон у клиента.
- Поле **isMobilePhoneConfirmed** показывает, подтверждён ли мобильный телефон клиента.
- Поле **pendingMobilePhone** передаёт номер мобильного телефона клиента, который ожидает подтверждения после смены.
- Узел **area** содержит в себе внешний идентификатор географической зоны покупателя, который передаётся в поле **externalId**, а также название географической зоны, к которой относится покупатель, передающееся в поле name.
- Поле **birthDate** передаёт информацию о дате рождения покупателя.
- Поле **sex** передаёт информацию о поле покупателя.
- Поле **changeDateTimeUtc** передаёт информацию о дате и времени регистрации покупателя.

### Описание узла Order

Узел **Order** возвращает подробную информацию по заказу клиента, переданному в запросе метода.

В узле возвращаются цены на позиции с учётом всех промоакций, которые потенциально могут к ним примениться.

Кроме того, возвращается список доступных скидок с детализацией по ним.

- Поле **processingStatus** передаёт статус процессинга заказа и принимает значение **Calculated** в случае успешного расчёта заказа.

  - **PersonalDiscountsCalculationIsUnavailable** — это статус недоступности расчёта персональных скидок (возникает при недоступности клиента или сервиса);
  - **DiscountsCalculationIsUnavailable** — это статус недоступности расчёта скидок (возникает при недоступности сервиса).
- Поле **totalPrice** — это финальная стоимость заказа после применения всех скидок и бонусов, с учётом стоимости доставки. Значение данного поля подставляется в аналогичное в запросе операции начала сохранения заказа.
- Поле **deliveryCost** передаёт стоимость доставки заказа.
- Массив **lines** передаёт информацию обо всех линиях заказа и о применённых к ним бонусах и скидках.

  - Узел **product** передаёт внешний идентификатор продукта в линии в поле **productId**.
  - Поле **lineId** передаёт идентификатор линии заказа.
  - Поле **lineNumber** передаёт номер линии заказа.
  - Поле **quantity** передаёт количество продуктов в линии.
  - Поле **basePricePerItem** передаёт стоимость единицы продукции в линии.
  - Поле **minPricePerItem** передаёт минимальную стоимость единицы продукции в линии.
  - Поле **discountedPriceOfLine** передаёт стоимость линии с учётом всех примененных скидок и бонусов.
  - Поле **status** передаёт статус позиций в линии.
  - Узел **customFields** передаёт дополнительные поля линии.
  - Массив **appliedPromotions** передаёт данные обо всех промоакциях, применившихся к линии.

    - Поле **type** передаёт тип применённой промоакции.
    - Узел **promotion** передаёт идентификатор промоакции, внешний или в системе Mindbox, в поле **Ids**. Поле **name** передаёт название промоакции. Поле **type** передаёт тип промоакции, внешняя или внутренняя (**external/Mindbox**).
    - Блок **limits** передаёт информацию о лимитах по конкретной промоакции:
    - Поле **type** передаёт информацию о том, что именно ограничивается лимитами, или по чему они агрегируются. Может принимать значение **orderLimit** (лимит на заказ), **personalLimit** (лимит на персональное использование акции), **groupLimit** (лимит на саму акцию).
    - Поле **untilDateTimeUtc** передаёт дату завершения действия лимита.
    - Узел **amount** передаёт информацию о количественных ограничениях лимита. Поле **type** может принимать либо значение **quantity**, либо значение **discountAmount**, то есть ограничивает лимит количество использований промоакции или же размер максимальной скидки для выдачи по акции соответственно. Поле **value** отображает значение лимита.
    - Узел **used** передаёт информацию о том, сколько лимитов по акции уже использовано и сколько ещё осталось. Поле **usageServiceStatus** показывает, можно ли доступны ли ещё лимиты для использования, и принимает значение **available** в случае, если лимиты ещё остались, и **unavailable** в случае, если лимиты уже израсходованы. Поле **amount** передаёт количество использованных раз.
    - Узел **balanceType** передаёт информацию о балансе, на который были начислены или с которого были списаны бонусные баллы. Поле **systemName** передаёт системное имя балльного счёта. Поле **name** передаёт название балльного счёте. Поле **amount** передаёт размер скидки в случае списания баллов и количество начисленных баллов в случае их начисления.
    - Поле **expirationDateTimeUtc** передаёт дату сгорания баллов.
    - Поле **amount** передаёт размер скидки.
    - Узел **coupon** передаёт значение применённого промокода в поле **code**.
    - Узел **pool** передаёт информацию о пуле, из которого был взят промокод. Поле **Ids** передаёт идентификаторы пула промокодов, внешние и внутренние (**externalId/MindboxId**). Поле **name** передаёт название пула промокодов. Поле **description** передаёт описание пула промокодов.
    - Массив **placeholders** передаёт информацию о тексте, отображаемом текстовой акцией, применённой к заказу. Поле **ids** передаёт идентификаторы зоны вывода текста. Узел **content** передаёт информацию о самом тексте для вывода.
- Массив **couponsInfo** передаёт информацию о промокодах клиента, применённых к заказу.

  - Поле **discountAmountForCurrentOrder** передаёт размер скидки промокодом к данному заказу.
  - Узел **coupon** передаёт информацию о применённом к заказу промокоде. Поле **code** передаёт значение применённого промокода.
  - Поле **status** передаёт статус промокода. Принимает одно из значений:

    - Unavailable — В данный момент использование промокодов недоступно;
    - NotFound — Промокод не найден;
    - NotIssued — Промокод не выдан;
    - Used — Промокод уже был использован;
    - YetNotActive — Срок действия промокода еще не наступил;
    - AlreadyNotActive — Срок действия промокода истек;
    - CanBeUsed — Промокод может быть использован в заказе;
    - CanNotBeUsedForCurrentOrder — Логика применения промокода не подходит для данного заказа;
    - Blocked — Промокод заблокирован.
  - Узел **pool** передаёт информацию о пуле, из которого был взят промокод. Поле **Ids** передаёт идентификаторы пула промокодов, внешние и внутренние (**externalId/MindboxId**). Поле **name** передаёт название пула промокодов. Поле **description** передаёт описание пула промокодов.
  - Поле **availableFromDateTimeUtc** передаёт информацию о дате и времени начала действия промокода.
  - Поле **availableTillDateTimeUtc** передаёт информацию о дате и времени окончания действия промокода.
  - Поле **usedDateTimeUtc** передаёт информацию о дате и времени использования промокода.
- Массив **bonusPointsInfo** передаёт информацию о баллах клиента.

  - Поле **status** передаёт информацию о статусе обработки балльного процессинга. Может принимать одно из 2 значений:
  - **Unavailable** — в случае, если операции с баллами не могут быть произведены;
  - **Success** — в случае, если процессинг успешно проведён.
  - Поле **availableAmountForCurrentOrder** передаёт максимальное количество баллов, которое возможно списать за данный заказ. Подробнее о том, зачем существуют ограничения по списанию баллов, можно прочесть [тут](https://help.mindbox.ru/docs/split-and-spread).
  - Поле **spentAmountForCurrentOrder** передаёт количество баллов, потраченное на заказ.
  - Узел **balanceType** передаёт информацию о балльном счёте, с которого списались баллы. В поле **systemName** передаётся системное имя балльного счёта. В поле name передаётся название балльного счёта.
  - Узел **balance** передаёт информацию о балансе баллов, лежащих на балльном счету, с которого произошло списание за заказ. Поле **total** передаёт информацию об общем количестве бонусов на счету. Поле **available** передаёт информацию о доступном для использования количестве баллов. Поле **blocked** передаёт информацию о заблокированных баллах на счету, то есть о тех, срок активации которых ещё не наступил.
- Массив **bonusPointsChanges** передаёт информацию об изменениях баланса по заказу.

  - Узел **balanceType** передаёт информацию о балансе, с которым произошли изменения. Поле **systemName** передаёт системное имя балльного счёта. Поле name передаёт название балльного счёта.
  - Поле **earnedAmount** передаёт количество баллов, которое будет начислено за заказ.
  - Поле **spentAmount** передаёт количество баллов, которое будет списано за заказ.

### Примечание

Если на проекте используется целочисленный балльный счет, то к заказу можно применить только количество баллов, кратное единице товаров. Например, на 2 единицы товара нельзя потратить нечетное количество баллов. В этом случае Mindbox автоматически округлит переданное количество баллов в меньшую сторону. Округление количество баллов вернется в узел discountsInfo/discountInfo/spentAmountForCurrentOrder.
