# Создание и обновление заказа (Процессинг)

## Набор шагов

| Шаг | Описание |
| --- | --- |
| Клиент - Авторизованный - Получить существующего, ищем по... | Предназначен для поиска клиента в базе данных Mindbox. Поиск может происходить по различным (одному или нескольким) параметрам, которые выбираются из выпадающего списка. |
| Заказ (Процессинг) - Создать или обновить заказ | Предназначен для того, чтобы создать в системе заказ и сразу списать и применить все необходимые бонусы клиента, которые используются в заказе. |
| Действие - Переопределить точку контакта | Предназначен для записи, в какой именно точке контакта (магазине) происходит сохранение заказа. Это нужно делать, например, для того чтобы применились (или не применились) акции, у которых выставлено ограничение по месту действия. Подробнее о промоакциях и их настройках можно прочитать [тут](https://help.mindbox.ru/docs/loyalty-program). |
| Клиент - Получить данные по текущему клиенту (Статус обработки, идентификаторы клиента) | Предназначен для того, чтобы в ответ операция вывела статус выполнения (успешно ли она рассчитала заказ), а также различные идентификаторы клиента для дальнейшего взаимодействия с ним. |

## Описание метода

Операция для создания или изменения состава заказа в режиме процессинга.

Операция принимает полный состав заказа с заранее рассчитанной в [операции расчета заказа](preorder.md) ценой. Рекомендуется создавать заказ в статусе «Оформлен».

- Если скидки с момента расчета изменились (акция перестала действовать, промокоды больше не действуют, не хватает баллов и т.п.), возвращается processing status: `PriceHasBeenChanged`.
  В этом случае необходимо заново рассчитать заказа с помощью [операции расчета заказа](preorder.md).
- Если вернулся статус `Processed`, вызов прошел успешно. После выполнения операции фиксируется дата создания заказа, а баллы, промокоды и подарочные карты, используемые в заказе, считаются использованными.

После успешной оплаты на кассе или на сайте необходимо передать статус Оплачен с помощью [метода изменения статуса заказа](update-order-status.md).
В случае проблем на стороне сайта или кассы и невозможности продолжения работы с чеком, дальше необходимо передать статус «Отменен» с помощью [метода изменения статуса заказа](update-order-status.md).

### Описание узла Order

Узел **Order** передаёт детальную информацию о рассчитываемом заказе.

- Узел **Ids** передаёт Id заказа во внешней системе.
  Id уже добавленного в Mindbox заказа указывается для того, чтобы изменить его состояние с новыми данными. Расчёт будет произведён с теми акциями и бонусами, которые были доступны клиенту на момент первого сохранения заказа.
- Узел **area** — это узел, передающий информацию о зоне (например, об области или часовом поясе), в которой оформляется заказ.
- Узел **bonusPoints** — это узел, передающий информацию о баллах к списанию за заказ. В поле **amount** необходимо передать количество баллов, которое хочется списать.

Если переданная сумма скидки баллами превысит стоимость заказа, система автоматически спишет число баллов, эквивалентное стоимости линий, не превышая его.

- Узел **coupons** — это узел, передающий информацию о промокодах, которые необходимо применить к заказу. В поле **Code** передаём значение нужного промокода.

В операциях оформления анонимных заказов не допускается применение реферальных промокодов. Если в теле запроса передан реферальный промокод, операция не выполнится с ошибкой «Промокод не применился».

- Поле **deliveryCost** передаёт стоимость доставки заказа. Доставка учитывается в общей стоимости при оплате, однако это поле необязательно.
- Поле **totalPrice** передаёт общую стоимость заказа, учитывая стоимость доставки (**deliveryCost**). Поле totalPrice следует забирать из ответа операции пречека по переданному в расчете составу заказа.
  Если за промежуток времени между расчётом заказа и его сохранением состав применимых к заказу скидок и бонусов поменялся (то есть если финальная стоимость заказа успела измениться), при создании заказа появится ошибка **PriceHasBeenChanged**. В таком случае нужно заново осуществить расчёт заказа и подставить в сохранение заказа обновлённый **totalPrice** или взять новое значение поля из подсказки в самой ошибке.
- Массив **lines** передаёт информацию обо всех линиях чека. В одной линии могут содержаться только одинаковые продукты. Для каждой отдельной линии есть свой узел, который передаёт информацию о ней. Узел содержит:

  - Узел **Product**, который передаёт информацию о конкретной позиции в линии. В нём указывается **Ids** продукта — идентификатор продукта во внешней системе.
  - Поле **lineNumber** — порядковый номер линии. Данное поле является обязательным, оно должно по порядку возрастать с каждой новой линией в заказе.
  - Поле **lineId** — уникальный идентификатор линии заказа. Это необязательное поле, оно может генерироваться автоматически.
    Несмотря на первичное сходство, lineNumber и lineId — это разные параметры. Различия проявляются в ситуации, когда при расчёте заказа одна линия поделилась на несколько. Подробно о ситуациях, в которых линия заказа может быть разбита на части, можно почитать [тут](https://help.mindbox.ru/docs/split-and-spread). Если происходит сплит и из одной линии чека мы получаем две, её номер меняется и увеличивается у новой линии, а их идентификатор остаётся прежним. Это сделано для того, чтобы по идентификатору было понятно, откуда взялась новая линия, с чем она была слита, а по её номеру было понятно, к какой именно стоимости (и к каким бонусам) апеллировать при возврате.
  - Поле **quantity** — количество товаров в линии. Может быть как целым, так и дробным числом, в зависимости от специфики товара. Принимает максимум 3 знака после запятой.
  - Поле **quantityType** — тип количества товара (целое или дробное). Его нужно передавать (с типом **double**) только в случае, если количество товара должно быть дробным.
  - Поле **basePricePerItem** — цена за единицу продукта в линии. Обязательное поле, у всех продуктов в одной линии значение должно быть одинаковым. Принимает максимум 2 знака после запятой.
  - Поле **minPricePerItem** — минимальная цена за единицу продукта в линии. Необязательное поле, показывает стоимость товара, ниже которой, даже при действии всех возможных скидок, опускаться нельзя. У всех продуктов в одной линии это значение должно быть одинаковым. Принимает максимум 2 знака после запятой.
  - Поле **customFields** — узел, передающий дополнительную информацию по продуктам в линии. Необязателен.
  - Поле **status** — системное имя статуса позиций в линии.
  - Узел **requestedPromotions** — это узел, для применения внешних акций.

    - В поле **externalId** указываем идентификатор внешней промоакции, которую нужно применить.
      - В поле **type** указываем, что это скидка (**discount**).
        - В поле **amount** передаём размер скидки в рублях.

### Создание внешних промоакций

Перед применением внешних промоакций их нужно добавить в систему через [API](import-external-promotions.md) или [операцию](save-external-promotion.md).
Они появятся в дереве промоакций, и после этого их можно будет применять к заказу.

- Узел **payments** передаёт информацию о способах оплаты, примененных к заказу. В поле **type** передаётся тип оплаты.
  При использовании подарочных карт, нужно передать сумму для списания с подарочной картой в этом узле.
- Узел **cashdesk** в поле **Ids** передаёт идентификатор кассы, где производится оплата. Поле необязательное.

## Описание ответа

Если все корректно, в ответе вернется информация о покупателе и его актуальный баланс, список выданных промокодов и подарочных карт, сообщения для печати на чеке.

Если сумма заказа больше неактуальна (промоакции закончились, недостаточно баллов), в ответ вернется статус **PriceHasBeenChanged** с описанием ошибки в поле **statusDescription**.

Подробнее о возможных ошибках можно прочесть в статье "[Лояльность](https://developers.mindbox.ru/page/loyalty-pos)".

### Описание узла Customer

Узел **customer** несёт информацию о клиенте, переданном в запросе операции.

Данные о клиенте, которые операция будет возвращать, можно указать в её настройках.

- Поле **processingStatus** показывает, какой статус процессинга у клиента, по которому производился расчёт заказа. Может принимать одно из значений:

  - **NotChanged** — было редактирование клиента без изменений;
  - **Changed** — было редактирование клиента с изменениями;
  - **Created** — клиент был успешно создан;
  - **NotFound** — клиент не найден в системе;
  - **Found** — клиент успешно найден в системе;
  - **AlreadyExists** — клиент уже существует;
  - **Ambiguous** — по указанным данным поиска найдено несколько клиентов.
- Поля **firstName**, **middleName** и **lastName** передают Имя, Отчество и Фамилию клиента соответственно, если они заполнены.
- Поле **email** передаёт почту клиента, если она заполнена.
- Поле **isEmailInvalid** показывает, валидный или невалидный e-mail у клиента.
- Поле **mobilePhone** передаёт номер мобильного телефона клиента, если он заполнен.
- Поле **isMobilePhoneInvalid** показывает, валидный или невалидный телефон у клиента:
- Поле **isMobilePhoneConfirmed** показывает, подтверждён ли мобильный телефон клиента:
- Поле **pendingMobilePhone** передаёт номер мобильного телефона клиента, который ожидает подтверждения после смены.
- Узел **area** содержит в себе внешний идентификатор географической зоны покупателя, который передаётся в поле **externalId**, а также название географической зоны, к которой относится покупатель, передающееся в поле name.
- Поле **birthDate** передаёт информацию о дате рождения покупателя.
- Поле **sex** передаёт информацию о поле покупателя.
- Поле **changeDateTimeUtc** передаёт информацию о дате и времени регистрации покупателя.

### Описание узла Order

Узел **Order** возвращает подробную информацию по заказу клиента, переданному в запросе метода.

В узле возвращаются цены на позиции с учётом всех промоакций, которые потенциально могут к ним примениться.

Кроме того, возвращается список доступных скидок с детализацией по ним.

- Поле **processingStatus** передаёт статус процессинга заказа и принимает значение

  - **Processed** в случае успешного расчёта заказа;
  - **PriceHasBeenChanged** в случае, если переданный totalPrice отличается от стоимости заказа, рассчитанной системой.
- Поле **Ids** передаёт идентификатор сохранённого заказа в Mindbox. Далее данный идентификатор можно переиспользовать при подтверждении или отмене транзакции.
- Массив **issuedCoupons** передаёт информацию о промоакциях с промокодами, применённых к заказу.

  - Узел **promotion** передаёт идентификатор промоакции, внешний или в системе Mindbox, в поле **Ids**. Поле name передаёт название промоакции. Поле **type** передаёт тип промоакции, внешняя или внутренняя (**external/Mindbox**).
  - Узел **coupon** передаёт значение применённого промокода в поле **ids**.
  - Узел **pool** передаёт информацию о пуле, из которого был взят промокод. Поле **Ids** передаёт идентификаторы пула промокодов, внешние и внутренние (**externalId/MindboxId**). Поле **name** передаёт название пула промокодов. Поле **description** передаёт описание пула промокодов.
- Массив **placeholders** передаёт информацию о тексте, который выводится текстовой акцией, применённой к заказу. Поле **ids** передаёт идентификаторы зоны вывода текста. Узел **content** передаёт информацию о самом тексте для вывода.
- Массив **bonusPointsChanges** передаёт информацию об изменениях баланса по заказу.

  - Узел **balanceType** передаёт информацию о балансе, с которым произошли изменения. Поле **systemName** передаёт системное имя балльного счёта. Поле **name** передаёт наименование балльного счёта.
  - Поле **earnedAmount** передаёт количество баллов, которое будет начислено за заказ.
  - Поле **spentAmount** передаёт количество баллов, которое будет списано за заказ.
