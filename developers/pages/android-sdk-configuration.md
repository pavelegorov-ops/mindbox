# Поля конфигурации Android SDK

## Пример объекта конфигурации

#### Пример со всеми полями

```
MindboxConfiguration.Builder(
applicationContext,
"",
""
)
.setPreviousDeviceUuid("Previous DeviceUUID")
.setPreviousInstallationId("PreviousInstallationId")
.subscribeCustomerIfCreated("Customer subscription status: TRUE / FALSE")
.build()
```

#### Пример готовой конфигурации

## Обязательные поля

### Domain API Mindbox

Это домен, по которому будет происходить обращение в API Mindbox.

Чтобы получить нужный домен для вашего проекта, сделайте следующее:

  

1. Перейдите на сайт проекта  
2. Перейдите в список операций через "Кампании" → "Список кампаний" → "Операции"   
3. Откройте любую операцию  
4. Нажмите «Посмотреть описание»  
5. Скопируйте домен из URL в спецификации

![](https://storage.yandexcloud.net/assets-developers-mindbox-ru/images/85d049ea13949fccd34fc1175669e8ec538a31f20e730b7fd98015040d117195-image.png)

Не передавайте в этом поле адрес административного раздела

## Endpoint External ID

Идентификатор точки интеграции, через которую будут вызываться операции на проекте.  
Значения указывает менеджер проекта в техническом задании на интеграцию.

## subscribeCustomerIfCreated

Если указан флаг о том, что нужно создавать клиента при инициализации SDK, то в этом параметре нужно указать состояние подписки на канал "Мобильные пуши"  
Параметр проставляется через код. Если вы хотите перед созданием анонима спросить пользователя о том, хочет ли он получать пуши, вам надо использовать "Продвинутый" сценарий интеграции

## Дополнительные поля конфигурации

## shouldCreateCustomer

Поле отвечает за то, нужно ли создать пустого пользователя в момент инициализации библиотеки.  
Принимает: `True` / `False`
По умолчанию: `True`

Если `True` - то при инициализации в Mindbox создается пустой пользователь.  
Если `False` - то пользователь не создается автоматом. Его надо создать через вызов операции.

Выставляйте поле в `False`, если в онбординге приложения настроен попап с вопросом о статусе подписке. В таком случае, вы можете самостоятельно определить с какими данными будет создан клиент.

## Поля конфигурации для перехода со старой интеграции

Если вы переходите со старой версии интеграции мобильных пушей, в которой использовался installationID, то вы можете использовать дополнительные параметры конфигурации, чтобы указать предыдущие данные клиента.

В случае указания этих параметров, они будут использоваться для поиска клиента.

- Если найдем, то присвоим ему данные новой интеграции.
- Если не найдем - создадим анонима

Если до внедрения SDK не было интеграции с мобильными пушами или данные не хранятся на устройстве, проигнорируйте эти параметры.

## setPreviousInstallationId

installationID, который был получен в рамках старой интеграции

## setPreviousDeviceUuid

deviceUUID, который ранее передавался в рамках интеграции при передаче installationID
